# v0.0.26

Re-introduces `gpo_powershell_path` so Group Policy operations run under native Windows
PowerShell, after verifying on a live in-domain host that the v0.0.24 regression does not
occur over a correctly configured WinRM or SSH transport.

## Added

- `gpo_powershell_path` provider setting (default `powershell.exe`). Group Policy operations
  (`adlc_backup_gpo`, `adlc_json_gpo`, `adlc_gpo_links`, `adlc_gpo_permission`,
  `adlc_gpo_security_filter`, `adlc_gpo_wmi_filter` and the `adlc_gpo` data source) run under
  Windows PowerShell, where the `GroupPolicy` module is native and returns non-deserialized
  objects; everything else keeps using `powershell_path` (`pwsh`). Set it to `pwsh` to force
  the compatibility layer, or to a full path if `powershell.exe` is not on `PATH`.

## Fixed

- Group Policy reads no longer lose nested object properties. Under the `pwsh` Windows
  PowerShell Compatibility layer, `Get-GPO` returns *deserialized* objects whose nested
  `.Computer.DSVersion` / `.User.DSVersion` come back null; routing these operations to native
  `powershell.exe` returns the real values.

## Changed

- On upgrade, GPO operations move from `pwsh` to `powershell.exe` by default (reverting the
  v0.0.25 change). This was re-validated end to end over WinRM (Kerberos) and SSH against a
  live domain controller: the gzipped bootstrap script is received and executed by
  `powershell.exe` on both transports, and `Get-GPO` returns native objects. If `powershell.exe`
  is unavailable, set `gpo_powershell_path = "pwsh"` to keep the compatibility layer.

## Internal

- Added live, host-gated transport/client tests that drive the stdin bootstrap under both
  PowerShell editions over WinRM and SSH, and assert GPO routing returns native objects
  (`internal/powershell/stdin_winrm_repro_test.go`,
  `internal/client/grouppolicy_routing_live_test.go`). They skip without `ADLC_HOST`.
- The WinRM smoke test now reads `ADLC_WINRM_KERBEROS_REALM` so it runs under Kerberos auth.
