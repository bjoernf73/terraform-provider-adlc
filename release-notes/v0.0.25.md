# v0.0.25

Reverts the v0.0.24 change that ran Group Policy operations under Windows PowerShell, which
broke them over WinRM.

## Fixed

- Group Policy operations (`adlc_backup_gpo`, `adlc_json_gpo`, `adlc_gpo_links`,
  `adlc_gpo_permission`, `adlc_gpo_security_filter`, `adlc_gpo_wmi_filter` and the `adlc_gpo`
  data source) again run under `powershell_path` (`pwsh` by default). v0.0.24 routed them to
  Windows PowerShell (`powershell.exe`), which did not receive the script over WinRM and
  failed every GPO read and write with *"remote PowerShell returned no JSON output"*.

## Removed

- The `gpo_powershell_path` provider setting introduced in v0.0.24. Every operation uses
  `powershell_path`. Under `pwsh` the `GroupPolicy` module still loads through the Windows
  PowerShell Compatibility layer (with its warnings); a native-module approach may return
  later once it works reliably over the transport.

## Added

- Read and query operations now also log to the `terraform-provider-adlc` event log on
  success (event ID 1002), alongside the existing change (1000) and failure (1001) entries.
