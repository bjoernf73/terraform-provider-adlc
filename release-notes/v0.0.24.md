# v0.0.24

Group Policy operations now run under Windows PowerShell by default, and linking a GPO onto an
OU that had no existing link works.

## Fixed

- `adlc_gpo_links` — creating a link on a target that had no existing link to the GPO failed
  with *"Make sure that a GPLink exists … Parameter name: Guid"*. The resource used `Set-GPLink`
  (which only updates an existing link) for creation; it now uses `New-GPLink` for links that
  don't exist yet and `Set-GPLink` only to update existing ones.
- `adlc_json_gpo` — the GPO version in Active Directory and SYSVOL was only bumped for registry
  (administrative template) settings, so a GPO whose content was Group Policy Preferences,
  scripts, audit, or a security template left the matching computer/user version at 0. The
  version now increments for every setting type, on the correct side (`versionNumber` packs the
  computer version in its low 16 bits and the user version in its high 16 bits).

## Added

- `gpo_powershell_path` provider setting (default `powershell.exe`). The `GroupPolicy` module
  is not native to PowerShell 7; under `pwsh` it loads through the Windows PowerShell
  Compatibility layer, which prints warnings and returns deserialized objects. GPO operations
  (`adlc_backup_gpo`, `adlc_json_gpo`, `adlc_gpo_links`, `adlc_gpo_permission`,
  `adlc_gpo_security_filter`, `adlc_gpo_wmi_filter` and the `adlc_gpo` data source) now run
  under Windows PowerShell, where the module is native. Set `gpo_powershell_path = "pwsh"` to
  force the compatibility layer instead.

## Changed

- On upgrade, GPO operations move from `pwsh` to `powershell.exe` by default. Every Windows
  Server ships Windows PowerShell with RSAT Group Policy, so this is normally transparent and
  removes the compatibility-layer warnings. If `powershell.exe` is unavailable or you prefer the
  old behaviour, set `gpo_powershell_path = "pwsh"`.

## Internal

- The embedded `GPRegistryPolicyParser` (`Registry.pol` byte I/O for `adlc_json_gpo`) now works under both PowerShell editions, not just pwsh 7.
- `adlc_gpo_links` is now exercised by the e2e and showcase acceptance configurations.
