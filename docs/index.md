# adlc Provider

ADLC is an Active Directory Lifecycle provider that manages directory objects and policy through PowerShell 7 commands on remote Windows systems over WinRM or SSH.

## Requirements

- PowerShell 7 (`pwsh`) on the target host. The provider may run on Windows Powershell, but all tests are conducted on PowerShell 7.
- The `ActiveDirectory` and `GroupPolicy` PowerShell module on the target host.
- WinRM (http or HTTPS on default ports 5985 or 5986, respectively) or OpenSSH (port 22) reachable from wherever Terraform runs

## Example Usage

```terraform
terraform {
  required_providers {
    adlc = {
      source = "bjoernf73/adlc"
    }
  }
}

# WinRM with NTLM authentication.
provider "adlc" {
  transport       = "winrm"
  host            = "dc1.contoso.local"
  username        = "CONTOSO\\terraform"
  password        = var.password
  winrm_auth      = "ntlm"
  powershell_path = "pwsh"
}

# SSH with password authentication.
provider "adlc" {
  alias           = "ssh"
  transport       = "ssh"
  host            = "dc1.contoso.local"
  username        = "terraform"
  password        = var.password
  powershell_path = "pwsh"
}
```

## Authentication

| Transport | Mechanisms |
| --- | --- |
| `winrm` | `basic`, `ntlm`, `kerberos` |
| `ssh` | password, private key |

Doing winrm over http is really an inside-domain-thing. Prefer HTTPS when runner is outside the AD domain. You may be able to get 
http between an outside-of-domain-runner and the target in-domain-host working, but you should not. It is simply better to use 
HTTPS, or SSH. Note that getting for instance SSH keys from Hashicorp or Azure vault in the terraform config is beyond the scope of this 
provider - there are of course other proper Terraform providers for that. However, in time I may supply examples on the topic of 
managing secrets, related to this provider of course.

### Optional

- `domain_controller` (String) Optional domain controller to pass to Active Directory cmdlets via `-Server`.
- `gpo_powershell_path` (String) PowerShell executable used only for Group Policy operations (`adlc_backup_gpo`, `adlc_json_gpo`, `adlc_gpo_links`, `adlc_gpo_permission`, `adlc_gpo_security_filter`, `adlc_gpo_wmi_filter` and the `adlc_gpo` data source). The `GroupPolicy` module is not native to PowerShell 7; under `pwsh` it loads through the Windows PowerShell Compatibility layer, which prints warnings and returns deserialized objects. These operations therefore default to Windows PowerShell (`powershell.exe`), where the module is native. Set this to `pwsh` to force the compatibility layer instead. Defaults to `powershell.exe`.
- `insecure` (Boolean) Skip certificate validation for WinRM TLS or host key validation for SSH.
- `password` (String, Sensitive) Remote account password. Used by WinRM and optional for SSH.
- `port` (Number) Remote port. Defaults to 5985 or 5986 for WinRM, and 22 for SSH.
- `powershell_path` (String) PowerShell 7 executable path on the remote Windows host. Defaults to `pwsh`.
- `ssh_host_key` (String) Authorized-key formatted SSH host public key.
- `ssh_known_hosts_path` (String) Known hosts file for SSH host key verification.
- `ssh_private_key_pem` (String, Sensitive) PEM-encoded private key used for SSH authentication.
- `timeout_seconds` (Number) Connection timeout in seconds. Defaults to 30.
- `username` (String) Remote account username.
- `winrm_auth` (String) WinRM authentication mechanism: `basic`, `ntlm`, or `kerberos`. Defaults to `basic`.
- `winrm_kerberos_ccache_path` (String) Optional Kerberos credential cache path on the machine running Terraform.
- `winrm_kerberos_config_path` (String) Path to `krb5.conf` on the machine running Terraform.
- `winrm_kerberos_realm` (String) Kerberos realm for WinRM Kerberos authentication.
- `winrm_kerberos_spn` (String) Optional Kerberos SPN override. Defaults to `HTTP/<host>`.
- `winrm_use_tls` (Boolean) Use HTTPS/TLS for WinRM.
